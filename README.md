# MediaLab EML (Экометт-Луч) — v1.0.0

Интерактивный живой мониторинг по теме «экономика замкнутого цикла промышленных
отходов»: читает источники (RSS, Telegram, Google News), оценивает релевантность,
тегирует по министерствам / гос.подразделениям / регионам / типу отходов —
и **накапливает всё в постоянную библиотеку** (`library.json`), не теряя старые
находки при каждом обновлении RSS-ленты. Каждый материал в таблице — рабочая
ссылка на первоисточник, с видимым доменом источника (например, `vedomosti.ru`,
`government.ru`), чтобы было сразу понятно, куда ведёт ссылка. Генерирует
`index.html` для публикации на GitHub Pages.

Название и дизайн — «MediaLab EML»: шрифты Cormorant Garamond (заголовки) +
Manrope (текст) + JetBrains Mono (моно-элементы), как в других дашбордах
(Export Intelligence Platform) — единый фирменный стиль. Версия дашборда
(`DASHBOARD_VERSION` в `ezc_parser_v2.py`) отображается в `<title>`, мета-теге,
рядом с заголовком и в футере — повышай её при следующих значимых изменениях.
В футере — копирайт-плашка (автор, версия, дата) и юридический дисклеймер,
по аналогии с EIP.

Сделан по образцу `ved_parser_v3.py` (парсер вакансий ВЭД): те же принципы —
сигналы с весами, правило перекрёстного подтверждения, приоритетные уровни.
Фильтрация — на стороне клиента (JS, без сервера): данные сериализуются в JSON
и рендерятся/фильтруются в браузере — дашборд остаётся статическим для GitHub Pages.

## Что внутри

- `ezc_parser_v2.py` — основной скрипт (сбор + скоринг + теги + накопление
  в библиотеку + генерация HTML)
- `sources.json` — список источников (RSS, Telegram, Google News по ключевым словам).
  Правь этот файл, чтобы включать/выключать источники (`enabled: true/false`) —
  Python-код трогать не нужно.
- `library.json` — накопленная библиотека всех найденных материалов (создаётся и
  пополняется автоматически при каждом запуске). **Не удаляй этот файл** — в нём
  вся история находок; удаление обнулит библиотеку.
- `run_parser.bat` — запуск двойным кликом
- `requirements.txt` — зависимости (requests, beautifulsoup4)
- `index.html` — результат работы скрипта (генерируется автоматически из library.json)
- `ezc_parser_v1.py` — старая версия (без тегов и без библиотеки), оставлена для
  истории, в работе не используется

## Установка (один раз)

1. Убедись, что установлен Python 3.11 (путь в `run_parser.bat` — поправь, если
   у тебя Python лежит в другом месте).
2. Установи зависимости:
   ```
   pip install -r requirements.txt
   ```

## Запуск

Двойной клик по `run_parser.bat`. Скрипт скачает материалы из всех источников,
оценит релевантность, протегирует по министерствам/регионам/типу отходов,
добавит новые материалы в `library.json` (старые из библиотеки не теряются,
даже если они выпали из RSS-ленты) и пересоберёт `index.html` из всей
накопленной библиотеки.

## Публикация на GitHub Pages (этап 1: локальный запуск + git push)

Ты выбрал: **новый отдельный репозиторий** для этого проекта. Шаги (один раз):

1. Зайди на github.com → New repository → назови, например, `ezc-monitor` →
   Public → без README (он уже есть здесь) → Create repository.
2. В этой папке выполни (замени `<URL_РЕПОЗИТОРИЯ>` на адрес, который даст GitHub):
   ```
   git init
   git add .
   git commit -m "ЭЗЦ Экометт-Луч: библиотека новостей и законодательства"
   git branch -M main
   git remote add origin <URL_РЕПОЗИТОРИЯ>
   git push -u origin main
   ```
3. На GitHub: Settings → Pages → Source: **Deploy from a branch** → Branch: `main` / `root` → Save.
4. Через пару минут дашборд будет доступен по адресу вида
   `https://<твой-логин>.github.io/ezc-monitor/`.

## Как обновлять дальше

Есть два способа. Оба делают одно и то же — публикуют свежие `index.html` и
`library.json` в репозиторий; разница только в инструменте.

### Вариант A: git

```
run_parser.bat            (пополняет library.json, пересобирает index.html)
git add index.html library.json
git commit -m "update"
git push
```

### Вариант B: publish.bat (без установки git, через GitHub API)

Настройка (один раз):

1. GitHub → Settings → Developer settings → Personal access tokens →
   Fine-grained tokens → New token. Repository access — только `eml_lab`.
   Permissions → Contents: **Read and write**.
2. Сохрани токен в файл `.github_token` в этой папке (только сам токен, без
   переносов строк). Этот файл уже в `.gitignore` — в репозиторий не попадёт.

Каждый раз, когда хочешь освежить дашборд:

```
run_parser.bat            (пополняет library.json, пересобирает index.html)
publish.bat                (публикует index.html + library.json на GitHub)
```

`publish_to_github.py` собирает коммит напрямую через GitHub API (Git Data
API — Contents API тут не годится, у него лимит ~1 МБ на файл, а
`library.json` обычно больше) и отправляет его в ветку `main`. Локальный git
для этого не нужен.

**Важно (для обоих вариантов):** коммить `library.json` вместе с `index.html`
— это единственное хранилище накопленной истории между запусками. Если его не
коммитить (или удалить), при следующем запуске на другой машине или после
переустановки библиотека начнётся с нуля.

Через минуту-две обновлённая версия появится на GitHub Pages. Кнопки "Обновить"
на самой странице, которая сама запускала бы сбор данных, в этой версии нет —
GitHub Pages отдаёт статические файлы и не может сама запускать Python. Это
осознанное решение этапа 1; полноценная кнопка "Обновить" на странице —
отдельная, более сложная задача (GitHub Actions), обсудим отдельно, если
понадобится.

## Фильтры дашборда

- **Приоритет** — по общему скорингу релевантности
- **Тип материала** — Продукт / Технология / Закон (`CONTENT_TYPE_RULES`) — по метаданным текста,
  один материал может нести несколько типов
- **Тип отходов** — Промышленные / Непромышленные (`WASTE_TYPE_RULES`)
- **Министерства** — Минэнерго, Минприроды, Минпромторг, ФАС и др. (`MINISTRY_RULES`)
- **Гос.подразделения** — Правительство РФ, Росприроднадзор, РЭО и др. (`GOV_BODY_RULES`)
- **Регион** — выпадающий список конкретных субъектов РФ (`REGION_RULES`, ~85 регионов)
- **Федеральный округ** — отдельные чипы (`OKRUG_DIRECT_RULES`); срабатывает и при прямом
  упоминании округа, и автоматически, если в тексте назван конкретный регион этого округа
  (`OKRUG_BY_REGION` — например, упоминание «Приморский край» само по себе ставит тег
  «Дальневосточный ФО», даже если слово «округ» в тексте не встречается)
- Плюс текстовый поиск по заголовку и тексту материала.

Регион и округ — независимые фильтры, их можно комбинировать с любыми другими (например,
Минэнерго + Дальневосточный ФО — без выбора конкретного региона). Настроив фильтры, можно
увидеть, например, только новости/документы Минэнерго по промышленным отходам в ДФО за
всё время работы библиотеки — не только за последний запуск.

Отдельный сигнал скоринга `industrial_waste_core` (самодостаточный, вес 20)
поднимает в топ материалы конкретно про ЗШО/промышленные отходы/техногенные
месторождения — независимо от остальных сигналов темы «экономика замкнутого
цикла» в целом.

Все правила — стартовые наборы ключевых слов, донастраиваем вместе по мере
появления реальных материалов.

## Таблица материалов, график, визуализация оценки

- **Порядок**: всегда хронологически, от свежих к старым — не зависит от приоритета/скоринга,
  и не меняется в зависимости от того, какие фильтры выбраны.
- **График «Публикации во времени»** над таблицей — считает материалы, которые проходят
  текущие фильтры, и группирует по датам. Переключатель масштаба: Месяц (по дням), Год
  (по месяцам), 5 лет (по кварталам), Всё время (по годам). Обновляется при каждом
  изменении фильтров.
- **Оценка материала** — вместо шкалы «важно/неважно» показывается «молекула»: центральный
  атом + 6 связей, число закрашенных связей пропорционально проценту скоринга; сам процент
  подписан рядом. Цвет молекулы соответствует уровню приоритета (ТОП/ВАЖНОЕ/ОБЩИЙ ФОН/ШУМ) —
  фильтр по приоритету (чипы) никуда не делся, изменилась только визуализация в строке.

## Архитектура: календарь жизненного цикла законов (law_dates)

Заложена схема данных для отслеживания дат нормативного акта — подписание (с номером),
вступление в силу, изменения/дополнения. Пока это **эвристика по регулярным выражениям**
(`extract_law_dates()` в `ezc_parser_v2.py`), которая распознаёт только явно написанные в
тексте даты (например, «от 07.05.2024 № 309», «вступает в силу с 15.06.2024», «с изменениями
от…») — точность не гарантирована, поля пустые, если в тексте таких фраз нет. Поле `law_dates`
уже попадает в JSON каждого материала, но на дашборде пока не отображается и не участвует
в фильтрах — это задел на будущее.

Полноценный и достоверный источник этих дат — открытые данные pravo.gov.ru (официальное
опубликование правовых актов), но это отдельный open-data формат (XML/XSD), не обычный RSS,
и требует отдельного парсера — сознательно отложено (см. «Источники, которые рассматривали»).

## Если Telegram / Google News не открываются (ошибки таймаута)

RSS-источники (infragreen.ru, vedomosti.ru, recyclingproductnews.com) — российские
и зарубежные домены, доступные напрямую. **t.me и news.google.com иногда
блокируются или сильно тормозятся** отдельными провайдерами/сетями в РФ — тогда
именно эти источники (и только они) будут показывать `ОШИБКА: Connection timed
out` / `Connection aborted` в консоли при запуске. Это внешняя сетевая проблема,
не баг скрипта — RSS-источники при этом продолжают работать и пополнять библиотеку.

Скрипт уже смягчает это:
- 2 повторные попытки с паузой перед тем, как считать источник недоступным;
- пауза между запросами к Google News (чтобы не словить блокировку по частоте);
- увеличенный таймаут (25 сек).

Если ошибки продолжаются и у тебя есть прокси/VPN — пропиши его перед запуском.
Открой `run_parser.bat` в блокноте и добавь строку с адресом прокси перед строкой
запуска python, например:

```
set EZC_PROXY=http://127.0.0.1:10809
```

Если прокси не нужен — просто не добавляй эту строку, поведение не изменится.

## Источники, которые рассматривали, но пока не добавили

- **Яндекс.Новости** — публичный RSS есть (`news.yandex.ru/daily.rss`), но это общая
  дайджест-лента без поиска по ключевым словам (в отличие от Google News у Яндекса
  нет публичного RSS-поиска по теме) — для узкой темы промотходов почти бесполезен.
- **Яндекс.Дзен** — механизм RSS у Дзена работает в обратную сторону (сайты отдают
  туда свой RSS, чтобы публиковаться в Дзене), а не наружу для чтения ленты по теме —
  забирать оттуда мнения/статьи по ключевым словам без хрупкого скрапинга поисковой
  выдачи не получится.
- **regulation.gov.ru** (проекты НПА) — очень релевантно (самая ранняя стадия
  законодательных изменений), но отдаёт данные через свой open-data формат
  (XML/XSD), а не обычный RSS 2.0 — нужен отдельный парсер, не просто новая строка
  в `sources.json`. Кандидат на отдельную задачу.
- **Минприроды (mnr.gov.ru), Росприроднадзор (rpn.gov.ru), Кремль (kremlin.ru)** —
  сайты либо не отдают простой RSS, либо это не удалось подтвердить программно
  (JS-рендеринг). Возможно, RSS всё же есть — нужно проверить вручную в браузере.
- Отраслевые порталы (ecoindustry.ru и подобные) и рубрики ТАСС/РИА «Экология» —
  не проверены; могут быть неплохим дополнением, но пока не подтверждены.

## Что настроено черновиком и потребует калибровки вместе

- Веса сигналов (`SIGNALS`) и пороги приоритетов (`PRIORITY_LEVELS`) — стартовые
  значения.
- Ключевые слова в `MINISTRY_RULES` / `GOV_BODY_RULES` / `REGION_RULES` /
  `WASTE_TYPE_RULES` — минимальный стартовый набор, расширяем по мере появления
  реальных материалов.
- География: сейчас RU/СНГ — основной охват, несколько англоязычных источников —
  для мировых рейтингов технологий/инвестиций.
